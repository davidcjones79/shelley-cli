Shelley Coordinator

Distributed task execution across multiple VMs

The Coordinator manages a pool of worker VMs that execute coding tasks in parallel. Each worker runs Shelley (the AI coding agent) to complete tasks like fixing bugs, adding features, or refactoring code.

Quick Start

  1. Start the Coordinator — Click the green "Start" button on the dashboard
  2. Scale Workers — Set the number of worker VMs (1-10) and click "Scale"
  3. Add Tasks — Enter prompts describing what you want done
  4. Monitor Progress — Watch tasks move from Queued → Running → Completed

Tasks

Tasks are units of work sent to workers. Each task contains a prompt describing what you want done.

Search & Filter

The dashboard provides tools to find tasks quickly:

  • Search box — Filter tasks by prompt text or task ID
  • Status filters — Click All, Queued, Running, Completed, or Failed to filter by status
  • Task count — Shows filtered/total (e.g., "3/9") so you know how many match

Task Statuses

StatusDescription
QUEUEDWaiting for an available worker
RUNNINGBeing executed by a worker
COMPLETEDSuccessfully finished
FAILEDEncountered an error

Task Actions

From the task list header:

  • Stuck — View tasks assigned to missing workers or running too long
  • Clear Done — Remove all completed and failed tasks from the list

From the task details modal (click a task):

  • Reset to Queued — Move a stuck or failed task back to the queue
  • Retry Task — Create a new task with the same prompt
  • View Artifacts — See files produced by the task

Example Prompts

"Fix the failing tests in auth_test.go"
"Add input validation to the signup form"
"Add a /health endpoint that returns JSON with uptime"
"Refactor handlers.go - split into separate files by resource"
"Find and fix SQL injection vulnerabilities"

Workers

Workers are exe.dev VMs that execute tasks. The coordinator automatically provisions and manages them.

Worker States

StateDescription
StartingVM is being provisioned
IdleReady to accept tasks
BusyCurrently executing a task
FailedVM creation or setup failed

Worker Health

Workers send periodic heartbeats. Health is indicated by color:

  • ● Healthy — Recent heartbeat
  • ● Warning — No heartbeat for 60s
  • ● Unhealthy — No heartbeat for 2 min
  • ● Dead — No heartbeat for 5 min (auto-replaced)

Task Groups

Groups let you batch related tasks together. All tasks in a group can share:

  • Repository URL (each task gets its own branch)
  • Base branch to start from
  • Progress tracking (X/Y completed)

Shared Repositories

When using Tailscale, repositories can be cloned once and shared across workers via git worktrees. This speeds up task startup significantly.

💡 Tip

Shared repos require Tailscale to be configured. Without Tailscale, each worker clones the repo independently.

Git Integration

Tasks can optionally work on a git repository:

  1. Specify repository URL and base branch when creating a task
  2. Worker creates a branch named task-{id}
  3. Worker commits changes and pushes to the branch
  4. View diff or create PR from task details

Git Worktrees

Git worktrees allow multiple working directories from a single clone:

  • Coordinator clones repo once to shared filesystem
  • Each task gets a worktree (lightweight checkout)
  • Workers access via SSHFS mount
  • Much faster than full clone per task

Artifacts

Tasks can produce artifacts — files that are saved and accessible after completion. Workers can upload files to the coordinator which are then viewable from the dashboard.

Real-time Updates

The dashboard uses WebSocket for real-time updates:

  • ● Live — WebSocket connected, receiving updates
  • ● Connecting... — Attempting to connect
  • ● Disconnected — Falling back to polling

Tasks API

EndpointMethodDescription
/api/enqueuePOSTAdd task to queue
/api/tasksGETList all tasks
/api/task?id=IDGETGet task details
/api/reset-task?id=IDPOSTReset task to queued
/api/clear-tasksPOSTClear completed/failed tasks
/api/stuck-tasksGETList stuck tasks

Create Task Example

curl -X POST /api/enqueue \
  -H "X-Coordinator-Token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Fix the bug in main.go"}'

CLI Reference

The coordinator can also be controlled via CLI commands in the Shelley chat:

CommandDescription
/coord startStart coordinator
/coord stopStop coordinator
/coord statusShow stats
/coord workersList workers
/coord tasksList tasks
/coord scale NScale to N workers
/coord drainDrain all workers
/coord add "prompt"Add a task
/coord group <repo> "p1" | "p2"Create task group with multiple prompts
/coord reposList shared repos

Internal APIs

These endpoints are used by workers and the dashboard internally:

EndpointDescription
/api/statsGet coordinator statistics
/api/wsWebSocket for real-time updates
/api/next-taskWorker requests next task
/api/task-startWorker marks task as started
/api/completeWorker reports task completion
/api/heartbeatWorker sends heartbeat
/api/worker-shutdownWorker self-shutdown notification
/api/sync-conversationSync conversation from worker to coordinator
/api/artifactsList artifacts for a task
/api/artifact/uploadUpload artifact from worker
/api/reset-stuck-tasksReset all stuck tasks to queued
/api/cleanup-workersClean up stale/dead workers
/api/shelley-binDownload shelley binary (for worker install)
⚠️ Authentication

All API requests require the header: X-Coordinator-Token: YOUR_TOKEN
